# Florence EST — Practice ASVAB Kiosk

A free-standing, installable practice-ASVAB app for Army recruiting
stations, built to run on a station iPad with no app-store install, no
login, and no ongoing maintenance once it's set up. Five practice test
variants, a 30-minute idle reset, offline-safe result syncing, and a
private per-station results dashboard.

**Station commander using this at your station?** Read
[`STATION_COMMANDER_GUIDE.md`](./STATION_COMMANDER_GUIDE.md) — that's the
whole guide, and it's the only file you need.

**Standing up a new station's copy of this?** Read
[`SETUP.md`](./SETUP.md) — a step-by-step checklist, start to finish.

## How it's put together

| Piece | What it is |
|---|---|
| `index.html` | The whole kiosk app — markup, styles, and logic in one file, served directly at the repo root (no separate redirect page). Per-deployment settings (recruiters, webhook URL, etc.) live in one `window.EST_CONFIG` block near the top — see the comment there. |
| `question-data.js` | The practice-test questions and ASVAB scoring tables, as a `window.__EST_STANDALONE__` global. Split out from the HTML because it's ~85KB nobody hand-edits. Regenerated by `tools/build-test-variants.js`. |
| `sw.js` | The service worker — precaches everything above so the kiosk works with no signal. Its `CACHE_NAME` has to be bumped on every deploy that changes a precached file, or installed iPads keep serving the old version. |
| `manifest.json` | PWA manifest — powers "Add to Home Screen" on iOS. |
| `apps-script/results-webhook.gs` | A **public** Google Apps Script web app the kiosk POSTs each result to; it appends a row to a Sheet and emails a formatted report. |
| `apps-script/roster-dashboard.gs` | A **private** ("only myself") web app — a filterable read-only view of that same Sheet. Kept as a separate deployment from the webhook above so the one public, unauthenticated endpoint never has read access to applicant data. |
| `question-bank/*.json` | Source question pools for test variants 2-5, consumed by `tools/build-test-variants.js`. |
| `tools/build-test-variants.js` | Node script that merges `question-bank/` into `question-data.js`. Only needed when adding/changing practice-test content. |

This repo's `index.html` and its own Apps Script deployments are the
canonical backend. A separate repo can point its own `resultsWebhookUrl`
at that same backend to get its own front end (its own recruiter list,
its own GitHub Pages URL) without standing up a second Sheet or a second
pair of Apps Script deployments — see `Florence_Practice_Test` for a real
example. `SETUP.md` covers both that pattern and when a station genuinely
needs its own separate backend instead.

## Testing changes locally

No build step. Serve the folder with anything static (e.g.
`python -m http.server`) and open `index.html` — or open it
directly from disk via `file://`, which also works since nothing fetches
across origins.

A fast way to drive a full test run without tapping through 50+ questions:
on the question screen, **Ctrl/Cmd+Enter** selects the correct answer and
advances immediately — built in as a proctor/testing shortcut, not hidden
or removed in production.
